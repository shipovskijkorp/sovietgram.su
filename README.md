# Sovietgram

Мессенджер с привычной логикой Telegram, советской визуальной айдентикой и небольшими тематическими пасхалками.

## Структура

- `config/` — настройки Django, ASGI/WSGI и корневые URL;
- `apps/accounts/` — учётные записи, профили, настройки и статус активности;
- `apps/messenger/` — контакты, личные чаты, сообщения и вложения;
- `templates/` — HTML-шаблоны;
- `static/` — CSS и JavaScript;
- `var/` — локальная база, собранная статика и пользовательские файлы, не коммитится;
- `deploy/` — заготовки для Nginx и systemd на VPS.

## Локальный запуск

Требуется Python 3.11+.

### Windows PowerShell

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
py manage.py migrate
py manage.py runserver
```

### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py runserver
```

Основные страницы:

- `/` — чаты;
- `/?archived=1` — архив;
- `/contacts/` — контакты и поиск по `@username`;
- `/saved/` — «Избранное»;
- `/profile/` — профиль;
- `/settings/` — тема и поведение ввода;
- `/u/<username>/` — публичный профиль.

## Реализовано

### Чаты

- личные диалоги и «Избранное»;
- закрепление, архивирование и отключение уведомлений для чата;
- поиск внутри переписки по тексту и именам файлов;
- черновики, сохраняемые в аккаунте;
- статус «в сети» / последняя активность;
- индикатор «печатает…»;
- счётчики непрочитанных и одинарная/двойная отметка доставки/прочтения;
- очистка истории у обоих участников.

### Сообщения

- текст до 4096 символов;
- ответы на сообщения с переходом к оригиналу;
- редактирование своих сообщений и подписей к медиа;
- удаление сообщения у обоих участников;
- пересылка в любой существующий диалог или в «Избранное»;
- несколько закреплённых сообщений;
- контекстное меню по правой кнопке и обычная кнопка действий на мобильных;
- копирование текста;
- ссылки в тексте становятся кликабельными;
- поиск может открыть старое сообщение вне последних 100 загруженных сообщений.

### Файлы и медиа

- Telegram-подобное окно предпросмотра перед отправкой;
- фото и видео альбомом или отдельными сообщениями;
- подпись к медиа;
- отправка исходного файла без обработки;
- произвольные типы файлов через безопасный download-endpoint;
- drag & drop и вставка изображения из буфера;
- прогресс загрузки;
- просмотр изображений поверх интерфейса;
- список общих медиа и файлов в информации о чате;
- до 10 файлов за отправку, 25 МБ на файл и 100 МБ суммарно.

Намеренно пока отсутствуют звонки, запись голосовых сообщений, стикеры, встроенный emoji-picker и GIF-функциональность. Обычные Unicode-символы в тексте не фильтруются.

## Перенос на VPS

Локально используется SQLite. На VPS предусмотрен PostgreSQL без изменения прикладного кода.

1. Установить зависимости из `requirements-production.txt`.
2. Скопировать `.env.example` в `.env` и настроить секрет, домены и PostgreSQL.
3. Выполнить:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check --deploy
```

4. Адаптировать пути и пользователя в `deploy/systemd/sovietgram.service`.
5. Установить `deploy/nginx/sovietgram.conf` и подключить HTTPS.

Пользовательские вложения лежат в `var/media/messages/`, аватары — в `var/media/avatars/`. Архитектура позволяет позже заменить локальное media-хранилище на S3-совместимое.

## Исходящая почта (Brevo SMTP)

В Sovietgram настроен SMTP-клиент для **отправки** транзакционных писем.
Подтверждение адреса при регистрации пока **не включено**: существующая
регистрация остаётся без изменений до отдельного внедрения и тестирования
механизма email-верификации.

1. Аутентифицируйте домен `sovietgram.su` в Brevo (DKIM/DMARC) и создайте
   отправителя `noreply@sovietgram.su`.
2. Получите **SMTP login** и отдельный **SMTP key** на вкладке Brevo
   **SMTP & API → SMTP**. Не путайте SMTP-ключ с паролем от сайта Brevo
   или API-ключом.
3. На VPS откройте `/opt/sovietgram/.env` и **добавьте**, не заменяя
   существующие настройки Django и базы данных:

   ```dotenv
   EMAIL_HOST=smtp-relay.brevo.com
   EMAIL_PORT=587
   EMAIL_USE_TLS=1
   EMAIL_HOST_USER=SMTP_LOGIN_FROM_BREVO
   EMAIL_HOST_PASSWORD=SMTP_KEY_FROM_BREVO
   DEFAULT_FROM_EMAIL="Sovietgram <noreply@sovietgram.su>"
   EMAIL_TIMEOUT=15
   ```

   Настоящий ключ никогда не добавляйте в Git, тикеты, скриншоты или
   системные журналы. Убедитесь, что файл `.env` читается пользователем
   `sovietgram`, но недоступен другим пользователям.
4. Проверьте настройки и отправьте **одно** тестовое письмо на адрес,
   доступный вам:

   ```bash
   cd /opt/sovietgram
   sudo -u sovietgram -H .venv/bin/python manage.py check
   sudo -u sovietgram -H .venv/bin/python manage.py sendtestemail your-inbox@example.com
   ```

   На сервере с `DJANGO_DEBUG=0` включён SMTP-backend. При локальной
   разработке с `DJANGO_DEBUG=1` письма выводятся в консоль (без
   реальной отправки). Если тест не дошёл, проверьте Brevo
   **Transactional → Logs**, папку «Спам» и доступность SMTP-порта 587
   с VPS. Статус принятия SMTP-сервером ещё не гарантирует доставку.

5. Для будущей отправки приложением перезапустите Gunicorn:

   ```bash
   sudo systemctl restart sovietgram
   ```

Изменений схемы БД нет. `EMAIL_BACKEND` можно переопределить
переменной `DJANGO_EMAIL_BACKEND`, например в тестовом окружении.

# Sovietgram

Мессенджер с привычной логикой Telegram, советской визуальной айдентикой и небольшими тематическими пасхалками.

## Структура

- `config/` — настройки Django, ASGI/WSGI и корневые URL;
- `apps/accounts/` — учётные записи, профили, настройки и статус активности;
- `apps/messenger/` — контакты, личные чаты, сообщения и вложения;
- `templates/` — HTML-шаблоны;
- `static/` — CSS и JavaScript;
- `var/` — локальная база, собранная статика и пользовательские файлы, не коммитится;
- `deploy/` — заготовки для Nginx и systemd на VPS.

## Локальный запуск

Требуется Python 3.11+.

### Windows PowerShell

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
py manage.py migrate
py manage.py runserver
```

### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py runserver
```

Основные страницы:

- `/` — чаты;
- `/?archived=1` — архив;
- `/contacts/` — контакты и поиск по `@username`;
- `/saved/` — «Избранное»;
- `/profile/` — профиль;
- `/settings/` — тема и поведение ввода;
- `/u/<username>/` — публичный профиль.

## Реализовано

### Чаты

- личные диалоги и «Избранное»;
- закрепление, архивирование и отключение уведомлений для чата;
- поиск внутри переписки по тексту и именам файлов;
- черновики, сохраняемые в аккаунте;
- статус «в сети» / последняя активность;
- индикатор «печатает…»;
- счётчики непрочитанных и одинарная/двойная отметка доставки/прочтения;
- очистка истории у обоих участников.

### Сообщения

- текст до 4096 символов;
- ответы на сообщения с переходом к оригиналу;
- редактирование своих сообщений и подписей к медиа;
- удаление сообщения у обоих участников;
- пересылка в любой существующий диалог или в «Избранное»;
- несколько закреплённых сообщений;
- контекстное меню по правой кнопке и обычная кнопка действий на мобильных;
- копирование текста;
- ссылки в тексте становятся кликабельными;
- поиск может открыть старое сообщение вне последних 100 загруженных сообщений.

### Файлы и медиа

- Telegram-подобное окно предпросмотра перед отправкой;
- фото и видео альбомом или отдельными сообщениями;
- подпись к медиа;
- отправка исходного файла без обработки;
- произвольные типы файлов через безопасный download-endpoint;
- drag & drop и вставка изображения из буфера;
- прогресс загрузки;
- просмотр изображений поверх интерфейса;
- список общих медиа и файлов в информации о чате;
- до 10 файлов за отправку, 25 МБ на файл и 100 МБ суммарно.

Звонки и стикеры пока отсутствуют. Голосовые сообщения, встроенная панель Unicode-эмодзи и GIF-вложения поддерживаются.

## Перенос на VPS

Локально используется SQLite. На VPS предусмотрен PostgreSQL без изменения прикладного кода.

1. Установить зависимости из `requirements-production.txt`.
2. Скопировать `.env.example` в `.env` и настроить секрет, домены и PostgreSQL.
3. Выполнить:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check --deploy
```

4. Адаптировать пути и пользователя в `deploy/systemd/sovietgram.service`.
5. Установить `deploy/nginx/sovietgram.conf` и подключить HTTPS.

Пользовательские вложения лежат в `var/media/messages/`, аватары — в `var/media/avatars/`. Архитектура позволяет позже заменить локальное media-хранилище на S3-совместимое.


## Подтверждение почты при регистрации

Поддерживаются одноразовые ссылки (24 часа), повторная отправка с паузой
120 секунд и подтверждение отдельным POST-запросом с CSRF-токеном (система
проверки ссылок в почтовом клиенте не может случайно активировать аккаунт).
В production ссылки строятся от канонического HTTPS-адреса
`https://sovietgram.su`, а страница подтверждения явно выставляет CSRF-cookie.

**По умолчанию функция выключена**: это позволяет сначала обновить код,
применить миграцию, проверить доставку Brevo и только затем включить её
для *новых* регистраций. Действующие активные аккаунты не блокируются
и не требуют повторного подтверждения.

Порядок включения на VPS:

1. Сделайте резервную копию базы данных, затем обновите `main`.
2. Примените миграцию `accounts.0008_email_verification`:

   ```bash
   cd /opt/sovietgram
   sudo -u sovietgram -H .venv/bin/python manage.py migrate
   sudo -u sovietgram -H .venv/bin/python manage.py check
   ```

3. Убедитесь, что реальная отправка Brevo работает (команда
   `manage.py sendtestemail` из раздела выше).
4. Добавьте в `/opt/sovietgram/.env`:

   ```dotenv
   SOVIETGRAM_REQUIRE_EMAIL_VERIFICATION=1
   SOVIETGRAM_PUBLIC_URL=https://sovietgram.su
   ```

5. Перезапустите службу `sudo systemctl restart sovietgram`.
6. Зарегистрируйте **тестовый новый** аккаунт со своим настоящим адресом.
   Новый аккаунт до подтверждения неактивен. После перехода по ссылке
   нажмите кнопку подтверждения и войдите с паролем.

Страницы: `/register/`, `/verify-email/pending/` (повторная отправка),
`/verify-email/<token>/`. Создание дополнительного аккаунта также
требует подтверждения; активная учётная запись в браузере не меняется.

**Важно:** смена адреса выполняется через настройки безопасности,
с подтверждением нового адреса, независимо от флага регистрации.
Старые активные аккаунты могут подтвердить текущий адрес, не меняя его.

## Восстановление доступа и смена почты

- На странице входа доступна ссылка «Забыли пароль?». Введите подтверждённый
  email; ответ не раскрывает наличие аккаунта. Ссылка действует один час.
  Новый пароль проверяется стандартными валидаторами Django; старые сеансы
  и сохранённые слоты мультиаккаунта становятся недействительными.
- Настройки → Конфиденциальность и безопасность → Электронная почта:
  введите новый (или текущий неподтверждённый) адрес и действующий пароль.
  Старый адрес остаётся действующим до явного подтверждения нового.
  Ссылка действует 24 часа. На прежний подтверждённый адрес после смены
  отправляется уведомление.
- Ссылки одноразовые; повторная отправка после 120 секунд аннулирует
  предыдущую ссылку. Смена пароля или адреса также аннулирует ранее выданные
  ссылки. Старые аккаунты без подтверждённой почты продолжают входить
  по паролю, но должны подтвердить адрес для восстановления доступа.
- Используется существующая SMTP-конфигурация Brevo и
  `SOVIETGRAM_PUBLIC_URL`. Перед перезапуском примените миграцию
  `accounts.0009_account_security_request` командой `manage.py migrate`.

Если возникнет проблема с доставкой, можно временно поставить
`SOVIETGRAM_REQUIRE_EMAIL_VERIFICATION=0` и перезапустить приложение.
Это отключит проверку для *новых* регистраций, но уже созданные
неподтверждённые аккаунты останутся неактивными до подтверждения почты.

## Исходящая почта (Brevo SMTP)

В Sovietgram настроен SMTP-клиент для **отправки** транзакционных писем.
Подтверждение адреса при регистрации пока **не включено**: существующая
регистрация остаётся без изменений до отдельного внедрения и тестирования
механизма email-верификации.

1. Аутентифицируйте домен `sovietgram.su` в Brevo (DKIM/DMARC) и создайте
   отправителя `noreply@sovietgram.su`.
2. Получите **SMTP login** и отдельный **SMTP key** на вкладке Brevo
   **SMTP & API → SMTP**. Не путайте SMTP-ключ с паролем от сайта Brevo
   или API-ключом.
3. На VPS откройте `/opt/sovietgram/.env` и **добавьте**, не заменяя
   существующие настройки Django и базы данных:

   ```dotenv
   EMAIL_HOST=smtp-relay.brevo.com
   EMAIL_PORT=587
   EMAIL_USE_TLS=1
   EMAIL_HOST_USER=SMTP_LOGIN_FROM_BREVO
   EMAIL_HOST_PASSWORD=SMTP_KEY_FROM_BREVO
   DEFAULT_FROM_EMAIL="Sovietgram <noreply@sovietgram.su>"
   EMAIL_TIMEOUT=15
   ```

   Настоящий ключ никогда не добавляйте в Git, тикеты, скриншоты или
   системные журналы. Убедитесь, что файл `.env` читается пользователем
   `sovietgram`, но недоступен другим пользователям.
4. Проверьте настройки и отправьте **одно** тестовое письмо на адрес,
   доступный вам:

   ```bash
   cd /opt/sovietgram
   sudo -u sovietgram -H .venv/bin/python manage.py check
   sudo -u sovietgram -H .venv/bin/python manage.py sendtestemail your-inbox@example.com
   ```

   На сервере с `DJANGO_DEBUG=0` включён SMTP-backend. При локальной
   разработке с `DJANGO_DEBUG=1` письма выводятся в консоль (без
   реальной отправки). Если тест не дошёл, проверьте Brevo
   **Transactional → Logs**, папку «Спам» и доступность SMTP-порта 587
   с VPS. Статус принятия SMTP-сервером ещё не гарантирует доставку.

5. Для будущей отправки приложением перезапустите Gunicorn:

   ```bash
   sudo systemctl restart sovietgram
   ```

Изменений схемы БД нет. `EMAIL_BACKEND` можно переопределить
переменной `DJANGO_EMAIL_BACKEND`, например в тестовом окружении.

## История и надёжность доставки

- История открывается последними 100 сообщениями или около первого
  непрочитанного. При прокрутке подгружаются страницы по 50 сообщений.
  Поиск и переход к ответу открывают окно около нужного сообщения.
- Позиция чтения (ID сообщения и смещение) сохраняется в браузере отдельно
  для аккаунта и чата. Из конца истории открываются новые непрочитанные.
- GET истории и polling не отмечают сообщения прочитанными. Отдельный POST
  подтверждает видимые входящие сообщения только в активной вкладке;
  отметка «прочитано до» не уменьшается и переживает удаление сообщения.
- Клиентские UUID и транзакционные квитанции отправки предотвращают
  создание дублей при потере HTTP-ответа. Повтор той же отправки возвращает
  существующее сообщение; повтор UUID с другим содержимым отклоняется.
  Поддерживаются текст, файлы/альбомы, голосовые, специальные сообщения,
  статьи и пересылки. Для текста ключ неотвеченной отправки переживает
  перезагрузку вкладки; файлы и голосовая запись для ручного повтора
  сохраняются в открытой странице, а не в постоянной офлайн-очереди.
- Примените миграцию `messenger.0014_read_cursor_send_receipt` перед
  перезапуском и выполните `collectstatic --noinput`.

## Управление непрочитанными чатами и удаление аккаунта

- Фильтры «Все», «Непрочитанные», «Группы», «Каналы» работают в основном
  списке и архиве. Выбор фильтра сохраняется в пределах вкладки для каждого
  аккаунта и раздела.
- В контекстном меню строки чата (ПКМ или Shift+F10) и меню открытого
  чата можно отметить его прочитанным или непрочитанным. Ручная отметка
  непрочитанного является личным напоминанием: она не отзывает уже
  выставленные собеседнику статусы прочтения. Повторное открытие в активной
  вкладке снимает только ту ручную отметку, с которой чат был открыт.
- Кнопка с двойной галочкой над списком по подтверждению отмечает
  прочитанными все видимые чаты текущего аккаунта, включая архив.
- Настройки → Конфиденциальность и безопасность → Удаление аккаунта:
  ручное удаление требует имя пользователя, действующий пароль и явное
  согласие с необратимыми последствиями. Используется существующий
  механизм удаления аккаунта, приватных переписок и передачи прав
  владельца непустых сообществ. При наличии других действующих слотов
  удаляется только текущий аккаунт, затем выполняется переключение.
- Перед перезапуском примените миграцию
  `messenger.0015_chatparticipant_marked_unread_at` и обновите статику.

## Реакции, упоминания и хештеги

- В контекстном меню сообщения доступны шесть реакций: 👍 ❤️ 🔥 😂 😮 👎.
  Повторный выбор снимает свою реакцию, выбор другой заменяет её.
  Счётчики хранятся на сервере и синхронизируются независимо от медиа.
  Одна реакция на пользователя и сообщение; список реагировавших не показывается.
- Упоминания в формате `@username` открывают профиль. При вводе `@`
  предлагаются участники открытого чата; выбор мышью, Enter или Tab.
  Упоминания пока не создают отдельные push-уведомления.
- Хештег `#тема` открывает поиск по тегу в текущем чате; ввод тега в
  глобальный поиск ищет его в доступных переписках. Поиск отличает
  `#тема` от `#тема2`. Упоминания также можно искать как отдельные токены.
- Перед перезапуском примените миграцию `messenger.0016_message_reactions`
  и обновите статические файлы.

## Форматирование, эмодзи и GIF

- Полный Markdown в сообщениях: CommonMark и GFM (заголовки, вложенные
  списки, чек-листы, таблицы, цитаты, ссылки, разделители, код), сноски
  и списки определений. Блоки кода подсвечиваются Pygments.
  Ctrl+B/I/U и панель форматирования помогают вставить разметку.
  Предпросмотр использует тот же серверный рендерер.
  Подчёркивание: `++текст++`; спойлер: `||текст||`.
  Стандартная разметка `__текст__` теперь означает жирный текст.
  HTML отключён; результат проходит независимую санитизацию.
  Внешние картинки загружаются только после явного нажатия, без Referer.
  Оригинал Markdown сохраняется в черновиках, пересылках и экспорте.
- Панель эмодзи содержит шесть тематических категорий Unicode и недавние
  эмодзи. Недавние сохраняются в браузере; внешние сервисы не используются.
- GIF можно загрузить из файлов через «Фото или видео», вставить из буфера
  обмена или отправить как скачиваемый файл. Анимация воспроизводится
  браузером без перекодирования. Проверяются реальный формат и кадры.
  Ограничения: 25 МБ на файл, 300 кадров, сторона до 4096 пикселей,
  до 4 млн пикселей в кадре и 80 млн суммарно на GIF. Аватары по-прежнему
  поддерживают только PNG, JPEG и WebP. Поиска GIF из внешнего каталога нет.
- Миграции базы для этих функций не требуются; обновите статические файлы.

Для обновления Markdown установите зависимости из `requirements-production.txt`
в существующее виртуальное окружение перед запуском Django. Новых миграций нет.

## Отложенные сообщения и тихая отправка

- Кнопка с часами рядом с полем сообщения и ПКМ по кнопке отправки
  открывают параметры: тихая отправка текста, планирование и список.
  В окне медиа/файлов также доступен переключатель тихой отправки.
- Отложенные текстовые сообщения (в том числе Markdown и ответы) сохраняются
  в отдельной очереди. До отправки получатель не видит их в истории, поиске
  и непрочитанных. Можно редактировать текст/время, отправить сейчас или
  отменить; сервер заново проверяет доступ, блокировки и ограничения.
  Медленный режим переносит попытку до разрешённого времени. Недоступный
  ответ или запрет отправки оставляют сообщение в списке с ошибкой.
- Максимум 100 активных запланированных сообщений на аккаунт, горизонт
  планирования — год. Браузер передаёт выбранное локальное время в UTC.
  Тихие сообщения остаются обычными непрочитанными, но не создают звуковой
  сигнал. Звуковые уведомления работают в активной вкладке после первого
  взаимодействия (ограничение браузеров); переключатель внизу списка
  чатов сохраняется локально для аккаунта. Учитываются отключённые
  уведомления конкретных чатов. Это не Web Push: при закрытом сайте
  звуковых уведомлений нет.
- Сейчас планирование доступно для текста, а тихая отправка для текста
  и медиа/файлов; голосовые, специальные сообщения и пересылки используют
  обычную отправку.

### Запуск очереди на VPS

После миграции `0017_scheduled_messages` и обновления приложения:

```bash
sudo install -m 644 deploy/systemd/sovietgram-scheduled.service /etc/systemd/system/
sudo install -m 644 deploy/systemd/sovietgram-scheduled.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sovietgram-scheduled.timer
sudo systemctl start sovietgram-scheduled.service
systemctl list-timers sovietgram-scheduled.timer
```

Таймер проверяет очередь примерно каждые 10 секунд, обрабатывает до 100
сообщений за запуск и догоняет просроченные после перезапуска VPS. Для
локальной проверки можно выполнить `python manage.py deliver_scheduled_messages`.
Без активного таймера сообщения не отправятся автоматически.

## Архив чатов

- Архив — отдельная персональная папка с живым предпросмотром, счётчиком
  и отдельным поиском (по чатам и сообщениям только внутри архива).
- ПКМ или длительное нажатие на чат открывает перенос в архив/из архива,
  закрепление, отключение звука (1 час, 8 часов, 2 дня, навсегда),
  отметку прочтения и множественный выбор. Свайп влево на мобильном
  переносит чат между основным списком и архивом.
- Порядок закреплённых чатов независим от новых сообщений. Перемещение
  между папками снимает закрепление в исходной папке; в новой можно
  закрепить снова. Пункты «Выше/Ниже» меняют порядок внутри папки.
- Меню самой папки: скрыть/показать архив, прочитать весь архив, выбрать
  чаты, открыть настройки и справку. Скрытый архив доступен из главного
  меню и временно раскрывается протягиванием списка вниз или прокруткой
  вверх у начала списка. Настройка хранится в аккаунте.
- Массовые действия применяются только к выбранным чатам текущей папки
  (до 200 за раз). «Прочитать весь архив» не затрагивает основной список.
  Архивирование не удаляет сообщения, не меняет черновики и не отмечает
  чат прочитанным. При включённом автоархивировании новые входящие личные
  чаты и принудительные добавления в сообщества не от контактов заглушаются
  и попадают в архив; добровольное вступление остаётся обычным.
- Требуется миграция `0018_archive_pin_order_and_voice_kind` (порядок
  закреплений и исправление пропущенной миграции выбора типа вложения).

### Автоматическое прочтение

Подтверждение прочтения вынесено в независимый клиентский модуль. Он
проверяет видимые входящие сообщения после открытия, прокрутки, изменения
размера, возвращения фокуса и восстановления сети, а также каждую секунду.
Фоновые вкладки, закрывающие чат модальные окна и загрузка исторического
окна не подтверждают прочтение. При ошибке запрос повторяется, а после
успешного подтверждения немедленно обновляется боковой список. Ручные
пометки непрочитанного из других вкладок сохраняют прежнюю защиту.

## Пользовательские папки чатов

- До 20 папок на аккаунт, название до 32 символов. Создание, редактирование,
  удаление и изменение порядка через кнопку с папкой в списке, главное меню
  или настройки. Удаление папки никогда не удаляет чаты и сообщения.
- Автоматические категории: контакты, не из контактов, группы, каналы и
  избранное. Можно исключать заглушённые, прочитанные или архивированные.
  Явные включения (до 200) переопределяют фильтры; явные исключения (до 200)
  имеют приоритет над всеми остальными правилами.
- Один чат может принадлежать нескольким папкам. В меню чата есть быстрый
  выбор папок: автоматически / включить / исключить. Закрепления и порядок
  закреплённых независимы внутри каждой папки. Массовые действия, поиск и
  «Прочитать папку» ограничены текущей папкой; счётчики обновляются при опросе.
- В настройках архива можно оставлять незаглушённые чаты в архиве, если они
  входят в пользовательскую папку после получения нового сообщения.
  Требуются миграции accounts 0010 и messenger 0019.
- Папки личные; публичных ссылок для совместного использования пока нет.

## Стикеры и предпросмотр ссылок

- Персональная библиотека: до 10 наборов по 40 статических стикеров.
  Создание, переименование, удаление набора, добавление PNG/WebP/JPEG до
  2 МБ и удаление отдельных стикеров. Изображения нормализуются в WebP
  не более 512×512 и 256 КБ с удалением метаданных. Стикер можно сохранить
  из доступного сообщения, если чат не защищён от копирования.
- Стикеры отправляются как независимые вложения, с ответом и тихой
  отправкой; черновик текста не стирается. Удаление набора не меняет
  ранее отправленные сообщения. Пересылка, история, автоудаление и
  ограничения медиа используют штатную логику сообщений.
- Под сообщениями со ссылкой появляется кнопка предпросмотра первой
  HTTP(S)-ссылки. По явному нажатию сервер получает только ограниченные
  текстовые метаданные (заголовок, описание, сайт). Внешние изображения,
  скрипты, cookies и автоматические фоновые запросы не используются.
  DNS проверяется, соединение привязано к разрешённому публичному IPv4,
  запрещены нестандартные порты, локальные адреса и опасные редиректы.
  Для production рекомендуется также ограничить исходящий трафик
  сервера к внутренней сети на уровне firewall. Некоторые сайты
  блокируют такие запросы; IPv6-only и страницы без HTML не поддержаны.
- Требуется миграция messenger 0020. Новых Python-зависимостей нет.
  Анимированные стикеры и публичные ссылки на наборы пока не поддержаны.

### Избранные и недавние стикеры

Стикеры из личных наборов можно добавлять в избранное звёздочкой. Недавние
содержат до 30 последних успешно отправленных стикеров; повтор той же
отправки не меняет историю использования. Можно убрать отдельный стикер
из недавних или очистить список. Оба списка хранятся в аккаунте и не
удаляют наборы. Удаление стикера из исходного набора убирает его из этих списков.

### Заявки на вступление

При создании ссылки-приглашения включите «Требовать одобрение администратора».
По такой ссылке новый пользователь сначала отправляет заявку. Владелец и
администраторы принимают/отклоняют её в настройках сообщества. Лимит ссылки
расходуется только при одобрении и создании нового участника; истечение
срока или исчерпание лимита запрещает одобрение. Отзыв ссылки отклоняет
ожидающие заявки. Повторная отправка не создаёт дубль. Пользователь может
посмотреть состояние и отменить заявку через «Мои заявки» в главном меню.
Обычные ссылки и прямое вступление в публичное сообщество работают как прежде.
До одобрения заявки членство и доступ к истории не предоставляются.
Миграция: messenger 0021. Дополнительные зависимости не нужны.

### Модерация сообществ

Владелец настраивает 8 отдельных прав администратора: информация, общие
разрешения, приглашения и заявки, модерация участников, удаление чужих
сообщений, закрепление, публикации (или обход общих ограничений группы),
редактирование чужих статей и завершение опросов. Старые администраторы
сохраняют прежние полномочия; изменять роли и передавать владение по-прежнему
может только владелец.

В настройках участников доступны удаление (без запрета повторного вступления),
бан с запретом повторного вступления и индивидуальные ограничения в группах
(текст, медиа, ссылки, приглашения и закрепление). Сроки: 1/8 часов, 1/7/30
дней или навсегда. Санкции локальны для сообщества и переживают выход.
Истёкшие санкции перестают действовать автоматически; разблокировка сама
не добавляет пользователя обратно в сообщество. История сообщений не
удаляется. В разделе блокировок и ограничений можно искать, редактировать
и снимать активные санкции. Новые действия записываются в журнал.
Реакции и голосование в опросах не входят в индивидуальные ограничения.
Требуется миграция messenger 0022.


### Расширенный поиск

- Глобальный поиск проверяет названия всех доступных переписок, включая старые и архивные. Результаты сообщений можно подгружать порциями по 18.
- Поиск внутри чата поддерживает подгрузку по 50 сообщений, фильтры по @username отправителя, диапазону дат (в часовом поясе клиента) и типу сообщения/вложения. Фильтры можно использовать без текста.
- Пагинация по идентификатору сообщения не сдвигается при поступлении новых сообщений. Скрытая история и удалённые сообщения не выдаются. Поиск по тексту и имени файла использует одинаковую логику подстроки и точных хештегов/упоминаний для SQLite и PostgreSQL (с учётом различий регистронезависимого сравнения СУБД).


### Локальная очередь отправки

- Текстовые сообщения, включая ответы и тихую отправку, сразу попадают в очередь (до 20 на чат). Неизвестный результат запроса повторяется с тем же UUID; 429 и временные ошибки используют задержку. Ошибки доступа/валидации требуют ручного действия. Удаление ожидающей записи прекращает повтор, но не отменяет уже принятую сервером отправку.
- Очередь хранит текст в sessionStorage отдельно для аккаунта и чата, переживает обновление этой вкладки и обрабатывается, когда соответствующий чат открыт. Закрытие вкладки может уничтожить очередь; другие устройства её не видят. Медиа пока не входят в очередь. При недоступном хранилище используется память вкладки. Не храните незавершённые сообщения на общедоступном устройстве.


### Соединение, уведомления и индикатор набора

- При потере соединения появляется индикатор, снимаемый после подтверждённого запроса к серверу.
- Отдельная кнопка колокольчика включает системные уведомления через разрешение браузера. Они не раскрывают текст/автора, открывают нужную переписку, учитывают заглушённые чаты и тихие сообщения. Требуются HTTPS и открытая вкладка; браузеры могут ограничивать фоновые запросы. Это ещё не Web Push при закрытом сайте. Фоновый запрос уведомлений не продлевает статус «в сети».
- В группах отображаются имена до трёх участников, которые недавно начали вводить сообщение; учитываются ограничения отправки и блокировки.


### Управление сообщениями

- Пересылка до 50 выбранных сообщений в 10 чатов за одну операцию; порядок внутри получателя сохраняется. Можно скрыть имя исходного автора и отправить без звука. Успешные отправки не повторяются при повторе оставшихся в открытом окне; UUID остаются прежними.
- Пересланные опросы являются независимыми новыми опросами без исходных голосов. Для викторины сначала нужно иметь доступ к правильному ответу (авторство или уже данный ответ). Списки задач сохраняют отметки, но не идентификаторы участников исходного чата.
- Контекстное меню позволяет скопировать ссылку на сообщение; доступ по ссылке определяется членством и видимостью истории. Копирование ссылок запрещено в чатах с защитой содержимого.
- Массовое удаление корректно повторяет только оставшиеся операции при частичном сбое. Поиск имеет один обработчик запросов, включая переход по хештегу.


### Проверка интерфейса

Управление группами/каналами открывается независимо от основного скрипта переписки. Ошибка загрузки выводится в самой панели с кнопкой повторного запроса. Режим выбора сообщений допускает пустой выбор до первого нажатия. При отказах API интерфейс не должен показывать ложное подтверждение успеха.

Автоматическая браузерная проверка запускается отдельным workflow **Browser controls** (Chromium). Она нажимает реальные кнопки на тестовом Django-сервере: разделы управления группой и каналом, сбои загрузки и повтор, выбор/редактирование/пересылку/удаление, поиск, стикеры, вложения, отложенные сообщения, папки и навигацию настроек. Локальный запуск: `pip install playwright`, `python -m playwright install chromium`, затем `SOVIETGRAM_BROWSER_TESTS=1 python manage.py test apps.messenger.test_browser_controls` (Linux/macOS). Используется отдельная тестовая БД; боевые переписки не затрагиваются.


### Общие медиа и файлы
В меню любой переписки и в профиле сообщества доступна галерея с категориями медиа, файлов, музыки, голосовых и стикеров, точными счётчиками и подгрузкой по 40 вложений. Из карточки можно перейти к исходному сообщению; изображения и видео открываются в отдельном просмотрщике с навигацией по загруженной подборке и скачиванием, когда оно разрешено. Голосовые и музыка воспроизводятся в галерее. Скрытые, очищенные, удалённые и просроченные сообщения не включаются в общие вложения.

Клиентский скрипт переписки изолирован от глобального пространства имён: совпадение имени CSRF-токена с функцией профиля больше не прерывает загрузку chat.js. Общий CSS принудительно соблюдает HTML-атрибут hidden. Эти регрессии выявлены первым запуском реальных браузерных тестов.


### Улучшения загрузки
- Выбор файла, drag-and-drop и вставка из буфера используют один контроллер. В отдельной отправке несколько файлов сохраняют порядок и стабильные идентификаторы; повтор продолжает не подтверждённые сервером операции. Кнопка «Остановить» прерывает текущий HTTP-запрос, но не отзывает уже принятые сообщения. Пока повтор возможен только в открытом окне отправки.
- В режиме фото и видео можно явно включить сжатие статических JPEG/PNG/WebP: до 1920 px по длинной стороне, если результат меньше исходного. Оригиналы, отправленные как файлы, GIF, анимация WebP/APNG и видео не перекодируются. Сжатие происходит на сервере после проверки, поэтому экономит место и трафик получателя, но не входящий трафик отправителя.
- Браузерный CI использует PostgreSQL 16, чтобы параллельные HTTP-запросы тестов не конкурировали за общую SQLite-базу в памяти.


Галереи и общие вложения используют отдельные WebP-миниатюры до 384 px, с первым кадром анимации и сохранением прозрачности. Полный файл загружается при открытии просмотрщика. Превью генерируется по запросу, браузер повторно проверяет права по ETag; отдельные файлы миниатюр на диске не создаются. При отсутствии исходного файла сервер возвращает 404 вместо 500.


### Надёжность синхронизации и чтение в группах
Клиент периодически сверяет версии до 40 уже загруженных сообщений; изменения текста, состояния специальных сообщений и реакций восстанавливаются даже за пределами временного курсора. Пропущенные удаления и истёкшие сообщения также исключаются. У автора сообщения в группе появился пункт «Кто прочитал»: список текущих участников, чей курсор чтения дошёл до сообщения и которые сохраняют доступ к нему, с постраничной выдачей. Это не журнал точного времени чтения и не доказательство открытия каждого отдельного сообщения.


### Уведомления
В настройках появился раздел «Уведомления»: звук, системные оповещения, счётчик непрочитанных в заголовке вкладки, обычные сообщения, упоминания и ответы. Категории и способы уведомления хранятся отдельно для аккаунта в данном браузере. Ответ имеет приоритет над упоминанием. Системное уведомление содержит только тип события и ведёт к сообщению, не показывает имя отправителя или содержание. Заглушённые чаты и тихие сообщения не оповещают, но учитываются в счётчике непрочитанных входящих сообщений. Пагинация по времени и ID обрабатывает всплески более 100 событий; оповещения старше 30 секунд намеренно не воспроизводятся. Для системных уведомлений по-прежнему требуется открытая вкладка и разрешение браузера.


### Реакции сообществ
Администраторы с правом управления разрешениями могут выбрать любые из шести доступных реакций или отключить все в группе/канале. Запреты проверяются на сервере и обновляются в открытых вкладках через polling. В группах можно отдельно запретить добавлять реакции ограниченному участнику. Старые реакции сохраняются и их авторы могут удалить их. В контекстном меню сообщения доступен список реакций с фильтрами и постраничной загрузкой; личности отображаются только для текущих участников группы/личной переписки с доступом к сообщению, в каналах показываются анонимные счётчики. Требуется миграция 0023.


### Статистика сообщества
В управлении группой/каналом доступна статистика за 7 или 30 календарных дней в часовом поясе пользователя: текущие участники, недавние вступления среди нынешних участников, сохранившиеся сообщения, число их авторов и текущие реакции на них, с графиками по дням. Доступ только с правом управления разрешениями. Это отдельный запрос без содержимого сообщений, не журнал просмотров/выходов или исторический счётчик удалённых сообщений.


### Обсуждения публикаций каналов
В управлении каналом включаются комментарии (по умолчанию отключены). Под каждой публикацией отдельная ветка с количеством комментариев; поддерживаются текст, ответы на комментарии, редактирование своих записей, удаление, загрузка более ранних записей и обновление открытой последней страницы каждые 5 секунд. Право публиковать в канале не требуется. Администратор с правом удаления сообщений может закрыть/открыть ветку и удалить чужой комментарий; в ограничениях подписчиков доступны реакции и комментарии. При отключении комментариев ветки скрываются, но не удаляются, при удалении/истечении публикации удаляются вместе с ней. Проверяются членство, бан, очищенная история, доступ к публикации и аккаунт. Повтор отправки с тем же UUID не дублирует запись. Миграция 0024 обязательна. Это отдельные текстовые обсуждения, пока без связанных групп, вложений, поиска и push-уведомлений.


### Двухфакторная аутентификация
В разделе конфиденциальности и безопасности можно включить TOTP: локальный QR-код, подтверждение первого одноразового кода и 10 одноразовых резервных кодов. Вход, добавление аккаунта и Django Admin используют один backend. Секрет шифруется Fernet с ключом, производным от DJANGO_SECRET_KEY; резервные коды хранятся как SHA-256 дайджесты случайных значений с 80 битами энтропии. Повторное использование TOTP-шага и резервного кода запрещено; после пяти ошибок второго фактора действует пятиминутное окно ограничения в БД. При изменении 2FA прежние сеансы и сохранённые слоты аккаунта перестают действовать, текущий сеанс обновляется. Восстановление пароля не отключает TOTP. Не меняйте DJANGO_SECRET_KEY без сохранения старого ключа в Django SECRET_KEY_FALLBACKS и переноса зашифрованных секретов. Обязательны зависимости из requirements.txt и миграция accounts 0011.

При включённой 2FA смена пароля и электронной почты, а также удаление аккаунта требуют действительного второго фактора. Настройка DJANGO_SECRET_KEY_FALLBACKS (список ключей через запятую) позволяет сохранить расшифровку TOTP при ротации ключа; не удаляйте прежние ключи до переноса всех секретов.


### Глобальная панель администрирования
Отдельная панель /control/ доступна только аккаунтам с глобальной ролью и включённой двухфакторной защитой. Эти роли не предоставляют права Django Admin. Модератор рассматривает жалобы и может удалить конкретное сообщение, на которое подана жалоба. Администратор также управляет обычными аккаунтами (блокировка, восстановление, отзыв сеансов), публичностью сообществ и приглашениями, просматривает журнал. Владелец платформы назначает/снимает роли администратора и модератора. Для первого владельца зарегистрируйте аккаунт, включите 2FA, затем на сервере выполните:
    python manage.py platform_admin ИМЯ_ПОЛЬЗОВАТЕЛЯ --reason "Initial platform owner"
После этого необходимо войти повторно. Другие владельцы назначаются только серверной командой; последнего владельца нельзя снять этой командой. Системные роли и данные 2FA не редактируются обычными настройками аккаунта. Не создаются предустановленные пароли. Панель не предоставляет произвольного доступа к личной переписке или вложениям; модератор видит только существующий текст сообщения, на которое пожаловался участник. Запрет публичности сообщества снимает @адрес, не удаляет его и не блокирует существующих участников/приглашения; отзыв приглашений — отдельная операция. Жалобы хранят описание пользователя и идентификатор объекта, но не копируют содержимое сообщения. Миграции accounts 0012, messenger 0025 и administration 0001 обязательны.


### Shared Redis cache and independent maintenance

Production can use one shared Redis cache for all Gunicorn workers. The
Django cache backs request throttles and other short-lived coordination;
sessions and messages remain in the database. Install Redis on the VPS,
keep it bound to loopback (do not expose port 6379), install updated Python
requirements, and set `SOVIETGRAM_REDIS_URL=redis://127.0.0.1:6379/1` in
the existing .env. For development or an unchanged VPS, the default remains
the local-memory cache. Do not silently fall back to local memory during a
Redis outage: that would disable shared rate limits. Verify connectivity:

```bash
sudo -u sovietgram -H .venv/bin/python manage.py shell -c 'from django.core.cache import cache; cache.set("deploy:probe", 1, 30); assert cache.get("deploy:probe") == 1; cache.delete("deploy:probe")'
```

Install and verify the maintenance timer before setting the opt-in flag:

```bash
sudo install -m 644 deploy/systemd/sovietgram-maintenance.service /etc/systemd/system/
sudo install -m 644 deploy/systemd/sovietgram-maintenance.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sovietgram-maintenance.timer
sudo systemctl start sovietgram-maintenance.service
sudo systemctl list-timers sovietgram-maintenance.timer
sudo journalctl -u sovietgram-maintenance.service -n 20 --no-pager
```

Only after successful execution set `SOVIETGRAM_BACKGROUND_MAINTENANCE=1`
in .env and restart sovietgram. Bulk expiry cleanup no longer runs in HTTP
requests. Each background run deletes at most 500 expired messages and 25
inactive accounts; accounts are checked again under the deletion lock.
Expired accounts remain unable to sign in or resume a session. If the timer
is not installed, the default 0 keeps the previous request-triggered cleanup.
No schema changes are required. The scheduled-message timer is unchanged.


### Automatic private backups

The backup command creates a database snapshot, the exact set of local media
files referenced by that snapshot (user avatars, chat avatars and message
attachments), the existing .env when present, and a SHA-256 manifest. SQLite
uses its online backup API plus quick_check; PostgreSQL uses pg_dump and
an exported consistent snapshot for media references. Install the PostgreSQL
client tools (pg_dump and pg_restore, matching or newer than the server's
major version) when using PostgreSQL. Local filesystem storage is supported.

The archive is verified before it is published; missing or changing files
cause failure and leave the previous archives untouched. A live backup does
not stop the website: files removed concurrently with the snapshot can cause
a failed run. For a guaranteed quiescent manual snapshot, stop the web and
scheduled/maintenance writers first, create and verify a backup, then resume
them. Archive verification alone is not a database restore test.

```bash
sudo install -m 644 deploy/systemd/sovietgram-backup.service /etc/systemd/system/
sudo install -m 644 deploy/systemd/sovietgram-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start sovietgram-backup.service
sudo systemctl enable --now sovietgram-backup.timer
sudo journalctl -u sovietgram-backup.service -n 20 --no-pager
sudo ls -lh /var/lib/sovietgram-backup/
```

Daily backups run around 03:30 server time and keep the seven newest
successful archives. Directory and file permissions are 0700 and 0600.
A manual backup can use a different private directory outside the
repository/media tree; use `--keep` to adjust rotation. Verify any archive:

```bash
sudo -u sovietgram -H .venv/bin/python manage.py backup_sovietgram --verify /var/lib/sovietgram-backup/ARCHIVE.tar.gz
```

**These backups contain private messages, attachments and potentially all
.env credentials; they are not encrypted.** Never publish or commit them.
Copy encrypted backups to a separate host or storage and limit access.
Local copies alone do not survive VPS loss or compromise. Keep the original
Django secret and any fallback keys; they are required to decrypt TOTP secrets.
If configuration is supplied outside .env, preserve it separately.

To rehearse a restore, verify the archive, extract it only into an empty
private staging directory, restore database.sqlite3 (SQLite) or load
database.dump with pg_restore --exit-on-error --no-owner --no-privileges
into a new isolated PostgreSQL database, and point MEDIA_ROOT/var/media at
the extracted media directory. Use the compatible application revision and
configuration, check migrations and run application smoke tests. Never
restore into the running production database or overwrite live files.
The command intentionally does not implement an automatic destructive restore.


### Устанавливаемое веб-приложение (PWA)

На HTTPS и localhost Sovietgram предоставляет manifest, иконки 192/512 и
service worker. В главном меню появляется «Установить приложение».
Chromium может показать системный диалог установки; на iOS используется
Safari → Поделиться → На экран Домой. Возможность установки зависит от
браузера. При недоступности сети показывается нейтральная офлайн-страница.
Service worker хранит только публичную офлайн-страницу и две иконки, не
кэширует личную переписку, страницы авторизованных пользователей, API,
аватары или вложения. Web Push и офлайн-просмотр истории не реализованы.
Требуется только обновление кода, collectstatic и перезапуск.


### Постоянная очередь текстовых сообщений

Текст, ответ, тихая отправка и стабильный UUID записываются в IndexedDB
до первой попытки HTTP. Очередь (20 сообщений на чат) переживает закрытие
вкладки и обычный перезапуск браузера. Записи разделены по аккаунту и чату,
атомарные транзакции и временная блокировка отправки между вкладками
предотвращают гонки; после сбоя вкладки блокировка истекает за 45 секунд.
Серверные квитанции сохраняют идемпотентность. Старые записи sessionStorage
переносятся после успешной записи в IndexedDB. При запрете IndexedDB
остаётся старая очередь вкладки. Отправка возобновляется при открытии
соответствующего чата в активной вкладке, а не фоновым service worker.
Неотправленный текст не шифруется и не синхронизируется между устройствами;
хранение зависит от политики браузера. На общем компьютере удаляйте
ожидающие сообщения перед выходом или очищайте данные сайта. Медиа в эту
очередь не входят.


### Мониторинг состояния сервера

Администратор и владелец платформы (с включённой 2FA) получают страницу
`/control/operations/`: доступность БД, задержка запросов к БД и кэшу,
свободное место, память, load average, состояние очереди отложенной
отправки и отметки запуска/успеха фоновых задач. Отметки сохраняются
атомарно в `var/ops/` при выполнении уже существующих systemd-служб.
Подробности исключений и секреты в интерфейс не передаются. Новых таймеров
не требуется; данные появятся после очередного запуска задач. Показатели
ресурсов относятся к хосту, а не обязательно к лимитам контейнера.

```bash
sudo -u sovietgram -H .venv/bin/python manage.py healthcheck
sudo systemctl list-timers 'sovietgram-*'
```

Команда завершается с ненулевым кодом при недоступности БД/кэша или
критическом заполнении диска. Публичный `/healthz/` предназначен только
для дешёвой проверки HTTP-доступности и не раскрывает внутренние метрики.
История показателей, внешние оповещения и мониторинг Nginx пока не
реализованы.
